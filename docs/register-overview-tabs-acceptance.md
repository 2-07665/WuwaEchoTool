# Register 養成總覽切換視圖驗收

2026-10-12。本次只修改本機，未部署。截圖和管理操作皆使用隔離瀏覽器的合成存檔，未存取使用者原本的瀏覽器資料。

## 介面

- 匯入角色、手動建立角色、最近使用角色、目前配置與繼續分析保留。
- 最近角色區域下新增「養成總覽 / 角色列表」分頁式切換，預設總覽。同時僅顯示一個內容面板，不再堆疊完整列表與總覽。
- 切換只更新 hidden、aria-selected 及 tabindex，不重建管理區域；角色、搜尋文字、來源篩選與展開狀態保留。支援方向鍵、Home、End。視窗重新取得焦點時仍保留目前視圖。
- 全角色概況顯示角色總數、已完成、待完成。四個畢業等級為細線四欄，Mobile 使用 2×2。
- 有可靠結果才顯示合計、均分、等級、稱號、評語。資料不足改為一句自然提示，不顯示四個「暫不可用」欄位；零角色不產生鑑定結果。
- 不再渲染「沿用 Classic」、儲存位置、互斥區間、優先規則等開發說明。無角色引導原本殘留的 Classic 文案也已清除。可展開的「鑑定說明」只有本次鑑定角色來源／數量及不同配置分別列計的簡短提示。

## 統計核對

計算公式、原有分級與來源優先規則未修改。這一輪沒有修改 base.js 或 Classic 的 index.js，也沒有修改分享圖、mcData、Echo schema、資料寫入或聲骸庫。

- 全角色概況：角色總數與未篩選的完整列表一致；完成判斷使用現有完整配置與有效保存分數条件。只新增展示用的 total / completed / remaining，沒有寫入存檔。
- 畢業分布及鑑定：保留有匯入角色就採匯入角色、否則採手動角色的既有規則。混合來源時，上方總角色數與本次鑑定角色數可能不同，未擅自改成合併統計。
- 同一遊戲角色的不同保存配置各佔一筆列表記錄；不按角色名稱合併。Dock 原本就拒絕重複 roleId 的損壞資料；沒有新增去重或評分規則。分布不會同時把手動與匯入來源加在一起。
- 未完成配置不進入畢業分布。部分資料完整時仍只顯示其已確認分布，不以子集產生整體平均或称号。
- 分級保持互斥且嚴格大於：>90、(80,90]、(70,80]、(60,70]。完整保留小數取捨及原來 16 種稱號判斷。
- 列表分數為原有即時計算值，鑑定沿用保存分數；若舊存檔分數過時，两者可能不同。這是原有行為，本次沒有更動或偷偷回寫。最終截图使用一致的合成分数，边界值另由单元测试覆盖。

## 驗證結果

- 全部 23 個測試檔通過；最後文案與無角色布局變更後，再次通過 i18n、Dock 及 overview 三個相關測試。
- Classic 對照 45 組資料與全部 16 種稱號仍通過；混合來源／不完整資料／三語測試通過。
- 真實 Edge 頁面：2 位、24 位不同角色；zh-TW、zh-CN、en；Desktop 1440×1100、Mobile 390×844。
- 總覽預設顯示，切到列表後所有角色管理列仍存在；搜尋、來源篩選、展開、键盤與焦點重建狀態通過；Mobile 無水平溢出。
- 管理驗收：刪除取消不寫存檔、確認只刪除指定合成角色；導航至正確角色、選取聲骸、打開原有編輯頁。既有保存、聲骸編輯與評分測試未變。
- 零角色、全部未完成、部分完成皆有三語截圖；資料不足沒有偽造零分或稱號；畫面沒有 Classic 等技術文案。
- 視圖切換、篩選與導航前後 mcData 位元組一致；只有測試中明確確認的刪除有預期寫入。
